## 七段式 → 块序列映射（每个 KP 课件的标准组织）

| 段 | 块序列 | 要求 |
|---|---|---|
| 1 悬念/动机开场 | `concept`（首段悬念）或 `callout(note)` | **30–80 字真实问题/历史故事/反直觉现象**（有趣例子库取材），让学习者在定义出现前就想知道答案。禁止"本节我们学习……" |
| 2 完整定义 | `definition`（+`quote` 原文佐证） | 教材级完整定义，逐字引用原文，带页码；易混术语先辨析 |
| 3 直觉解释/类比 | `text` + `thinking` | 通俗图景先行 + 1 个类比；thinking 抛一个问题让学习者先想；允许拟人化/场景化（"栈像一摞盘子"），但定义段必须回到严谨术语 |
| 4 定理与证明 | `theorem`（proof 每步注依据） | 该 KP 涉及的定理完整呈现；无关定理不硬塞 |
| 5 例题（≥2 有正有反） | `example` ×≥2 + `callout(pitfall)` | 正例走通、反例踩坑；例题优先套有趣外壳（生活场景/历史名题），不要光秃秃符号题 |
| 6 高密度可视化 ≥2 | `anim`/`diagram`/`chart`/`interactive` 至少两种 | 优先级：anim 模板可表达 > mermaid > chart > interactive（≤1）；factsheet「交互命题候选」是选题依据；算法类必给逐步过程（anim 帧或 mermaid 分步） |
| 7 检验与总结 | `quiz` ≥3 + `summary`（+`keypoint` 1–3 张） | quiz 覆盖必用事实与易错点；summary.links 交叉引用真实块 id |

## 有趣教学硬标准（2026-11-11 用户点名，缺任一项即返工）

1. **悬念开场**：第 1 块必须是悬念/故事/反直觉现象（30–80 字），从下面取材或现场造：
   - 历史名题（哥尼斯堡七桥、四色地图、Hanoi 5800 亿年、RSA 公钥为何破不了）
   - 生活场景（排队/扑克牌/快递分拣/族谱/导航软件）
   - 反直觉现象（"0.999...=1"、"负数开平方"、"strlen 的 O(1) 骗局"）
   - 工程钩子（ZIP 压缩、奇偶校验、编译器 AST、数据库索引）
2. **≥1 个有趣例子**：正文里的例子至少一个套生活/历史/工程外壳；纯符号题必须包装（"给手链涂色"而非"给 n 个点染色"）。
3. **画面感语气**：正文允许把对象拟人化/场景化（"零因子是两个好数相乘消失了"）；定义/证明段保持严谨。
4. **可视化讲事实**：图形块前后的 md 要指图说话（"看上图的第 2 步"），不让图孤零零站着。

## 容量硬标准（validate_course_blocks 会按 warn 级报告，缺了必须补）

| 项 | 标准 |
|---|---|
| 正文字数 | 全部 md/proof/steps 累计 **≥2500 字**（中文计） |
| example | ≥2 个（至少 1 反例/踩坑向） |
| quiz | ≥3 个 |
| 可视化块 | **≥2 个**（不同块型；算法/数据结构 KP 首选 anim） |
| interactive | ≤1 个（能不用就不用——anim/mermaid 能表达的不升级） |
| blocks 总数 | ≤500（schema 硬限，一般 15–30 块正好） |
| 单块 md | ≤200k 字符（schema 硬限） |

代码块/公式/表格不计入正文字数——它们是正文之外的密度。

## digest 产出规范（生成课件的同一次任务输出）

```json
{ "core": "≤500 字：该 KP 的核心结论/公式/机理，学习者忘了一切之后应该记住的", 
  "takeaway": "≤500 字：一句话收获 + 与下一个 KP 的衔接点" }
```

- 只写已学事实，不前瞻未来 KP（除 takeaway 的一句衔接）。
- 跳过的 KP 会在上下文里以 gap 出现——你生成时要用一句话向学习者交代空缺（"上一节 X 我们跳过了，不影响本节"）。

## 重新生成模式（用户在应用里点「重新生成课件」触发）

1. `get_lesson` 读回旧版课件：**保留**仍正确的页码引用与例题结构，修薄弱段。
2. 用户没有给具体反馈时，默认**全面强化**：有趣开场重写、可视化补到 ≥2、quiz 易错点覆盖核对。
3. 覆写落盘走同一 `save_kp_lesson`（同 lessonId）；digest 若有更新同步 `save_kp_digest`。

## 发出前自检（机检之外，你自己的最后一道关）

**机检项**（validate_course_blocks 返工循环覆盖，≤2 轮）：
- [ ] schema 全字段合法；三条铁律通过
- [ ] 容量硬标准六项达标
- [ ] mermaid 语法可解析；echartsOption 纯 JSON 无回调
- [ ] interactive 的 bridgeImports 与实际 import 一致且全在白名单
- [ ] coding 引用的 exerciseId 已用 save_exercise 落盘
- [ ] quiz answer 与 options key 对应（多选逗号分隔无空格）

**自检项（原人审项——校对页已移除，这步必须自己做扎实）**：
- [ ] **页码回查 ≥3 条**：随机抽 3 个 book 块，按 ocrFile 读 OCR 原文（run_code 读文件），核对摘录确实出现在该页；对不上的当场改页码或改摘录
- [ ] 数字逐字符一致（单位/下标/进制前缀）
- [ ] 悬念开场是真的悬念（不是"本节我们学习……"）
- [ ] 可视化 ≥2 且直接回答了 factsheet 的交互命题
- [ ] 每个图形块前后有指图说话的正文

## 返工循环

1. `validate_course_blocks(lesson)` → 错误清单
2. 按错误逐条修（铁律/错误回喂最高优先级）
3. 回到 1，最多 **2 轮**；仍失败 → `set_kp_gen_failed(kpId, 原因)` 并如实汇报，不要把坏文档硬塞给 save_kp_lesson
